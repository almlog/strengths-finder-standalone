## タスク詳細

### Task 1: 出社2/出社3ギャップの休憩補正
**Status:** COMPLETED

**問題:**
- 楽楽勤怠は午前有休の日に所定休憩（12:00-13:00）が有休帯に含まれるため、休憩時間を計上しない
- 休憩時間修正申請も運用ルールで使用不可
- 現場では「退社→出社2」の打刻ギャップで休憩を表現する運用があるが、分析ではこのギャップが休憩と認められず `break_violation` を誤検出
- 実例: 13:00-19:00勤務 + 19:45-20:58残業（実働7:13）で、19:00-19:45の45分休憩が計上0のまま違反判定

**対応:**
- `XLSX_COLUMN_INDEX` に出社2/退社2/出社3/退社3（Index 23/24/30/31）を追加
- `AttendanceRecord` にoptionalフィールド追加（既存テストへの影響なし）
- `getGapBreakMinutes()` 新設: 「出社2 − 退社」＋「出社3 − 退社2」を算出（欠落・負値は0）
- `analyzeDailyRecord()` の休憩判定で、既存の自動付与調整後の休憩にギャップを加算
- 違反判定ルール自体（6h超45分/8h超60分）は不変。加算しても不足なら従来どおり違反

**検証:**
- 新規テスト `AttendanceService.BreakGapCorrection.test.ts` 11件（/Dパターン・/5パターン・不足時の違反維持・出社3・リグレッションガード）
- 実データ961レコードで違反2件→0件。解消は午前有休＋出社2運用の2日のみ
- `/D`（休憩1:00固定）・`/5`（残業時の夕方15分自動加算）の両カレンダーで動作確認
- `CI=true npm run build` 成功、ユーザー目視確認済み

**備考:**
- カレンダーコード（/D, /5）自体は解釈していない。計上休憩の分数のみで判定するため、将来のカレンダー追加にもそのまま対応
